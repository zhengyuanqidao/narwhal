# 私域运营 知识地图（MOC）

> 这一领域我沉淀了什么、它们之间什么关系。新条目入库后挂到这里。

## 核心问题

一个只有几千好友的小盘，怎么在不加人的前提下把月销做上去？——答案是**服务强度按价值分层**，而不是把同样的动作对所有人重复更多遍。

## 知识结构

### 基础概念
- [[私域不是加好友而是分层运营]] — 私域的价值在分层，不在好友数量；KPI 定在好友数必然做出死库。

### 方法与 SOP
- [[社群冷启动的7日节奏]] — 立规矩 → 给价值 → 造参与 → 首转化，顺序不能换；D1 不发商品是成败关键。

### 踩坑与教训
- [[别用红包做拉新钩子]] — 红包拉来价格敏感人群，会反向带偏选品与定价，隐性成本远大于拉新成本。

### 经验案例
- [[8000好友做成12万月销社群盘]] — 分层改造 2 个月，月销 3.2 万 → 12 万，好友只涨 300。

## 知识关系

```
分层运营（概念·根）
 ├─ 决定 → 社群冷启动7日节奏（方法）
 ├─ 反例 → 红包拉新（踩坑：用错人校准商品结构）
 └─ 结果 → 12 万月销社群盘（案例）
```
