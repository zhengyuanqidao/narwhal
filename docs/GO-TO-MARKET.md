## 零、先纠正一个前提

你说"免费版也好，能收费也好，都行"——**这里不是"都行"，而是有硬约束**。

官方原文（`/docs/monetization` §3.1）：

> 资产选择是否付费后，后续将不支持修改，请确认后再发布资产。

也就是说：**免费资产不能原地转付费**，所以答案不是二选一，而是做两个资产：一个免费换量，一个付费换钱。

⚠️ **2026-11-12 重要修正**：这里的「不可改」只指**付费方式**（免费 / 一次性 / 按月）。**价格数值是可以改的**——平台控制台有「修改价格」「价格已更新」，规则是每年限 N 次、仅管理员可操作、次年 1 月 1 日重置。上一版把 FAQ 的「暂不支持转付费」误读成「价格也锁死」，已纠正。完整证据见 [PLATFORM-AUDIT.md](../../workbuddy-assets/docs/PLATFORM-AUDIT.md) §2。

## 二、双资产策略：一个内核，两个壳

| | ① `narwhal` 技能（免费） | ② 「知识库编译师」专家（付费） |
|---|---|---|
| 上架到 | 技能市场 | 专家市场 |
| 形态 | `SKILL.md` + `scripts/` + `references/` | 专家壳（人设 + 方法论 + 3 条引导）+ **内嵌同一个 skill** |
| 价格 | ¥0 | 一次性买断 ¥99（早期）/ ¥199（有量后） |
| 作用 | 换安装量、换认知、换 GitHub star | 换现金流 |
| 用户画像 | 技术型，喜欢自己调 | 非技术，要"点一下就能用" |
| 出口 | 装了 skill 的人会去 GitHub 看源码 | 买了专家的人会问"能不能帮我们建" → 交付线索 |

**为什么同一个东西能一个免费一个收费**：开源不是让步，是**筛子**。会自己配环境、读脚本、改参数的人，本来就不会付那 ¥99——他们留下 star 和 issue，帮我们改 bug。付 ¥99 的人买的是"有人替我把这套流程调好了"。这两拨人几乎不重叠，所以定价不会互相蚕食。

**为什么 skill 免费、专家收费，而不是反过来**：
- skill 的详情页只有一段描述 + 3 条示例，没有"角色感"，用户不会为一段说明付钱；
- 专家的卡片有职业头衔、擅长领域、任务示例、使用量，是"请到了一个人"的叙事，¥99 才站得住；
- 平台政策也支持这个顺序：技能免费上、专家收费上，两个资产互不干扰。

## 三、上架清单（可直接照做）

### 3.1 免费技能：`narwhal`

现有 `SKILL.md` 是本地格式（只有 `name` + `description`），**市场要求额外字段**。需补齐：

```yaml
---
name: narwhal
display_name: 文档变知识库
display_name_en: Docs to Wiki
description: 把散落在本地和云端的个人经验、对话、笔记、文档自动扫描、按领域聚类，沉淀为多个结构化领域知识库（个人 wiki），并可将领域知识库编译输出为该领域的工作技能（SOP/检查清单/实战手册/Skill）。当用户想"建立知识库/个人 wiki/专家体系"、"扫描我的文档"、"沉淀经验"、"整理我的方法论"、"深潜/ExpertLoop"、想要某领域的"SOP/工作手册/技能包"时使用。
description_zh: 把会议纪要、方案、复盘变成带数字和反例、能直接照做的条目
description_en: Turn meeting notes, plans and post-mortems into executable entries with numbers and counter-examples
version: 1.0.0
author: zyqd
examples_zh:
  - "把这个文件夹里的会议纪要和方案，变成一页能查的知识库"
  - "检查我的知识库哪些条目太空洞、哪些已经过期"
  - "把这份复盘变成一条带数字和反例、能直接照做的经验"
examples_en:
  - "Turn the meeting notes and plans in this folder into a searchable knowledge base"
  - "Audit my knowledge base for hollow or outdated entries"
  - "Turn this post-mortem into a reusable entry with numbers and counter-examples"
---
```

> **2026-11-12 定稿（Owner 拍板）**：`display_name = 文档变知识库`。选它的理由是免费技能的 KPI 是安装量/搜索覆盖（"文档""知识库"都是高频搜索词），而「编译」是自造词、留给付费专家「知识库编译师」立品类。
> 注意 `description` 保留**触发词式**原文——这是本地 Skill 供模型判断何时加载的核心，不能删；平台口径的「一句话能力描述」由 `sync_narwhal.py` 在同步到市场壳时覆盖，内核仍是唯一事实来源。
> `author` 已统一为 `zyqd`（与 git 提交署名一致）；GitHub 账号为 `zhengyuanqidao`。开放平台市场展示名若与之不同，提交前替换并 `bump patch`。
> 诚实风险：`文档变知识库` 会引来「以为是归档工具」的用户，**靠 `description_zh` 首句区分「整理文件」与「产出判断」**，不靠改名。

> 三个 `examples` 会显示在详情页的「试试这样用」，**这是转化率最高的两块位置之一**（另一块是首图描述）。要写用户真会说的话，不要写功能名。

`displayDescription` 草稿（45 字，卡在区间内）：

> 把散落文档编译成有边界、可执行的条目，生成 AI 与新人能照做的 SOP，支持增量更新与版本管理。

`quickPrompts` 三条：

1. 把我这个文件夹的文档整理成可执行的知识库
2. 检查我的知识库哪些条目太空洞
3. 把这份访谈整理成一条可复用的经验

### 3.4 公司主体改变收入结构（关键）

| | C 端零售（专家市场） | B 端合同（对公交付） |
|---|---|---|
| 客户 | WorkBuddy 个人用户 | 有文档囤积的团队（POSITIONING 的 ICP） |
| 单价 | ¥99 买断 | ¥2k–8k/领域 + 季度订阅 |
| 合规 | 平台代收代结 | **需要对公账户 + 发票——只有公司能做** |
| 角色 | **获客渠道 + 信任背书**（使用量公开显示） | **利润中心** |
| 抽成 | 平台服务费 1%（内测）+ 微信 0.6%，合计约 1.6%；长期按 10–30% 压力测试 | 无平台抽成 |

**结论：公司主体下，专家市场的 ¥99 不是利润来源，是获客入口。** 专家卡片的使用量是公开的信任背书，买过专家的团队用户就是 B 端销售线索。个人主体只能做左列，公司主体两列都做——这是"我有科技公司"这句话的最大价值。

财务注意：对公结算收入自行纳税申报；平台收入有 30 天账期 + 7 天无理由退款，现金流模型要按"成交额 × (1−抽成) × 退款系数、延迟 30 天"估。

## 四、定价

| 资产 | 模式 | 价格 | 理由 |
|---|---|---|---|
| narwhal 技能 | 免费 | ¥0 | 换量，不参与收入 |
| 知识库编译师 | **一次性买断** | ¥99 起 | 见下 |

**为什么是买断不是订阅**：
- 平台订阅制要求"订阅期内可持续使用"，隐含持续交付义务；
- 我们的增量价值（季度体检、CHANGELOG）需要人肉投入，C 端 ¥39/月 撑不起；
- 买断与"库在你手里、永久可用"的产品叙事一致；
- **付费方式选定不可改**（但价格数值可每年限次调整），买断与「库在你手里」的叙事一致；

**为什么是 ¥99 起步**：低于 ¥100 属冲动区间，退款摩擦（7 天无理由）影响小。价格**可改**（每年限 N 次、仅管理员、1 月 1 日重置额度），所以不必为了「怕以后不能涨」把首发价一步定高；但仍不做 ¥9.9——低价会长期压低品类价格锚，且改价配额有限。

⚠️ **定价前必须在客户端专家市场里翻 20 个同类付费专家，看实际价格带**。官方文档不给价格分布，拍脑袋定会踩空。

### 4.1 什么能改、什么不能改（2026-11-12 系统核查后重写）

> 完整证据见 [PLATFORM-AUDIT.md](../../workbuddy-assets/docs/PLATFORM-AUDIT.md) §2。本节上一版结论有误，已作废。

| 项 | 能否修改 | 依据 |
|---|---|---|
| 免费 ↔ 付费 | **不能** | `/docs/monetization` §3.1 明文「资产选择是否付费后，后续将不支持修改」；FAQ「暂不支持转付费」 |
| 买断 ↔ 订阅 | **不能** | 控制台 `paySetting.mode.desc`：「付费方式发布上架后不可更改」（once / monthly 两条说明均写明） |
| **价格数值** | ✅ **能改** | 控制台 `price.edit = 修改价格`、`price.updated = 价格已更新`、`amountOnly.limitHintDynamic = 付费金额每年可修改{total}次` |
| 改价的约束 | 每年限 N 次；仅管理员可操作；次年 1 月 1 日重置；金额 1–9999 整数 | 控制台 `quotaExhausted` / `payEditDenied` / `amount.hint` |
| 内容与版本 | 能 | `action.republish = 更新版本`；Connector 明文「修改文件并递增 version 后重新提交审核」 |
| 专家/技能名称 | ⚠️ 官方无「不可改」明文 | 展示名由能力包解析，改名需重提审；见 PLATFORM-AUDIT §2.5（待核实） |

**处理原则改为：价格按「可改但有年度配额」规划。**

- 首发价可以低价试错，不必为了「永久不能涨」而一步到位；
- 但次数有限且仅超管可操作，定价主表仍需一张（见 PLAN-REVIEW A2，已降级为一致性问题）；
- 「涨价靠发新资产」降级为备选，用于**改付费方式**或重大改版；
- 仍不做 ¥9.9：低价锚会长期影响品类认知，且改价配额不值得浪费在试错上。

**仍然成立的一条坑**：免费上架的 `narwhal` 技能**不能原地转付费**，以后想卖技能版只能另建付费资产。这正是第一节要求「一开始就分两个资产」的原因。

⚠️ 四项待核实：每年改价次数 N 具体是几、改价对已购用户是否生效 / 是否退差价、改价是否触发重审、名称能否改。入驻后在「我的资产」里点开「编辑 / 更新版本 / 修改价格」三个入口一次性验完。

## 五、运营：三件事，一个现实预期

### 现实预期先摆出来

**这两个市场目前没有强自然流量分发。** 推荐位按"使用热度 / 新上架 / 编辑精选"排，本质是把已有热度再分配。指望"上架就有量"不成立。所以所谓运营，实际是**自己带人进市场**，市场只负责承接转化。

### 三件事

**① 搜索词工程（上架当天做完）**
`tags` 3 个 + `description` 里塞用户真会搜的词：知识库、SOP、经验、文档整理、培训、交接、个人知识管理。用户搜的是"怎么把文档变成能用的东西"，不是"知识编译"。

**② 站外内容：给结果，不给功能**
唯一有效的素材是**前后对比**：一堆乱文档 → 一张 MOC + 12 条带数字的条目 + 一份 CHECKLIST。发小红书 / 即刻 / V2EX / 公众号，标题写结果（"把 200 篇文档压成 30 条能直接干活的 SOP"），不写"我做了个 skill"。技术社区（V2EX、GitHub）指向免费 skill，非技术社区指向专家市场。

**③ 使用量是唯一硬指标**
卡片上公开显示，前 100 次使用决定后面能不能被推荐。所以免费 skill 要**极力降低首次使用门槛**：默认给 demo 素材，用户一句话就能看到成品，不要让他先准备文档。

## 六、三个必须先验证的风险

| # | 风险 | 为什么致命 | 怎么验 |
|---|---|---|---|
| 1 | **付费资产加密 + 云端运行 + 禁用自定义模式** | narwhal 卖点是「库在你本地、可移植、离线可用」。官方 FAQ 确认加密且云端运行；控制台另确认「付费能力必须加密，不可关闭」「用户不可使用自定义模式调用」。真问题不是「有没有 Bash」（Read/Write/Bash 是系统内置工具，无需声明），而是**云端沙箱的路径边界**与**加密后 `scripts/*.py` 能否执行** | 上架 ¥1 探针，验三件事：可写目录范围、加密后脚本是否仍可执行、产物能否落到用户可见位置 |
| 2 | **收费资格有前置门槛** | 控制台「开通条件」要求「已有 ≥1 个通过审核的技能/专家」，不是签约完就能卖 | **W1 顺序改为：先上免费 narwhal 并过审 → 解锁资格 → 再上 ¥1 探针** |
| 3 | **市场自然流量低** | 上架 ≠ 获客；但控制台有「推广管理」（专属推广渠道），此前假定「平台无任何分发工具」需修正 | 上架后 2 周看安装数，<50 说明只能靠自传播；同时试官方推广渠道 |

探针新判读口径：若本地路径不可写，付费专家改成「云端生成 → 导出 zip → 用户下载落本地」，仍然成立，但 `displayDescription` 里「支持增量更新」这句要改口径。
