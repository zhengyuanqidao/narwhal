# Narwhal 上架与获客计划（v0.1）

> 本文替代 `POSITIONING.md` 第六节的 P0 阶段：**先把分发做出来，再谈后端收入。**
> 所有平台约束均来自官方开放平台文档（`open.workbuddy.cn/docs/expert`、`/docs/skill`、`/docs/monetization`），已核实项标注 ✅，需客户端实测项标注 ⚠️。

## 零、先纠正一个前提

你说"免费版也好，能收费也好，都行"——**这里不是"都行"，而是有硬约束**。

官方原文（`/docs/monetization` §3.1）：

> 资产选择是否付费后，后续将不支持修改，请确认后再发布资产。

也就是说：**先免费试水、不行再改付费，这条路不存在。** 所以答案不是二选一，而是**做两个资产**：一个免费换量，一个付费换钱。一旦想清楚这点，后面的动作就是唯一的。

## 一、平台机制（已核实，决定了怎么打）

| 机制 | 事实 | 对我们的含义 |
|---|---|---|
| ✅ 两个市场 | **技能市场**（`SKILL.md` + 可选目录）与**专家市场**（专家包 `plugin.json`）并存 | 同内核可上两次 |
| ✅ 两条收费模式 | 一次性买断 / 按月订阅，仅这两条 | 只能二选一，且**不可改** |
| ✅ 入驻流程 | 填资料（个人/企业）→ 审核（微信 24h 内返）→ 微信扫码签约 | 一次做完，别在上架当天才办 |
| ✅ 结算 | 订单产生 **30 天**后可提现；平台抽服务费 + 微信支付手续费（**比例未公开**） | 现金流有 30 天账期 |
| ✅ 退款 | 一次性与订阅均 **7 天无理由**，同一资产**最多退 3 次** | 定价低于 ¥100 时退款摩擦可忽略 |
| ✅ 加密与云端 | 付费资产"加密防护，并在云端运行，已购用户也不能轻易复制蒸馏" | **最大变量，见第七节风险 1** |
| ✅ 展示与流量 | 专家卡片公开显示**使用量**与开发者信息；首页按**使用热度 / 新上架 / 编辑精选**推荐 | 有新上架窗口期，使用量是马太效应 |
| ✅ 搜索 | 支持按**名称、标签、描述**匹配 | `tags` + `description` 就是 SEO |
| ✅ 专家可内嵌技能 | `plugin.json` 的 `skills: ["./skills/xxx"]`，agent frontmatter 的 `skills: [xxx]` 预加载 | **不必做两份内容** |

## 二、双资产策略：一个内核，两个壳

| | ① `narwhal` 技能（免费） | ② 「知识库编译师」专家（付费） |
|---|---|---|
| 上架到 | 技能市场 | 专家市场 |
| 形态 | `SKILL.md` + `scripts/` + `references/` | 专家壳（人设 + 方法论 + 3 条引导）+ **内嵌同一个 skill** |
| 价格 | ¥0 | 一次性买断 ¥99（早期）/ ¥199（有量后） |
| 作用 | 换安装量、换认知、换 GitHub star | 换现金流 |
| 用户画像 | 技术型，喜欢自己调 | 非技术，要"点一下就能用" |
| 出口 | 装了 skill 的人会去 GitHub 看源码 | 买了专家的人会问"能不能帮我们建" → 交付线索 |

**为什么同一个东西能一个免费一个收费**：开源不是让步，是**筛子**。会自己配环境、读脚本、改参数的人，本来就不会付那 ¥99——他们留下 star 和 issue，帮我们改 bug。付 ¥99 的人买的是"有人替我把这套流程调好了"。这两拨人几乎不重叠，所以定价不会互相蚕食。

**为什么 skill 免费、专家收费，而不是反过来**：
- skill 的详情页只有一段描述 + 3 条示例，没有"角色感"，用户不会为一段说明付钱；
- 专家的卡片有职业头衔、擅长领域、任务示例、使用量，是"请到了一个人"的叙事，¥99 才站得住；
- 平台政策也支持这个顺序：技能免费上、专家收费上，两个资产互不干扰。

## 三、上架清单（可直接照做）

### 3.1 免费技能：`narwhal`

现有 `SKILL.md` 是本地格式（只有 `name` + `description`），**市场要求额外字段**。需补齐：

```yaml
---
name: narwhal
display_name: 知识库编译
display_name_en: Wiki Compiler
description: 扫描本地文档，把散落经验编译成带边界与反例的条目，再生成可直接执行的 SOP / CHECKLIST / PLAYBOOK
description_zh: 把散落文档编译成 AI 与新人能直接照做的知识库
description_en: Compile scattered documents into an executable knowledge base
version: 1.0.0
author: <作者名>
examples_zh:
  - "把这个文件夹里的文档整理成能用的知识库"
  - "检查我的知识库哪些条目太空洞"
  - "把这份会议纪要变成一条可复用的经验"
examples_en:
  - "Turn the docs in this folder into a usable knowledge base"
  - "Audit my knowledge base for hollow entries"
  - "Turn this meeting note into a reusable piece of expertise"
---
```

> 三个 `examples` 会显示在详情页的「试试这样用」，**这是转化率最高的两块位置之一**（另一块是首图描述）。要写用户真会说的话，不要写功能名。

### 3.2 付费专家：「知识库编译师」

结构（对齐官方模板）：

```
knowledge-compiler/
├── .codebuddy-plugin/
│   └── plugin.json
├── agents/
│   └── knowledge-compiler.md
├── skills/
│   └── narwhal/           ← 直接复用，不重写
├── avatars/
│   └── expert.png         ← 512×512 PNG，≤500KB，插画风
└── README.md
```

`plugin.json` 关键字段（**全部必填，缺一解析失败**）：

| 字段 | 值 | 备注 |
|---|---|---|
| `name` | `knowledge-compiler` | 小写+连字符，与 `plugin` 字段一致 |
| `version` | `1.0.0` | 语义化 |
| `author` | `{name, email}` | |
| `agents` | `["./agents/knowledge-compiler.md"]` | |
| `expertType` / `agentName` | `agent` / `knowledge-compiler` | |
| `skills` | `["./skills/narwhal"]` | 内嵌核 |
| `displayName` | `{zh: "知识库编译师", en: "Wiki Compiler"}` | 客户端里**创建后不可改名** |
| `profession` | `{zh: "经验萃取与知识编译专家", en: "Knowledge Compilation Expert"}` | |
| `displayDescription` | 见下，**中文须 40–50 字** | 硬约束 |
| `avatar` | `avatars/expert.png` | 512×512 / ≤500KB / 插画风 |
| `categoryId` | `04-DataAI` | 该类别官方描述含"知识管理"，正对口 |
| `tags` | 固定 3 个：知识管理 / 经验萃取 / SOP 生成 | 影响搜索命中 |
| `quickPrompts` | 固定 3 条（见下） | 卡片展示 |
| `defaultInitPrompt` | **必须等于 quickPrompts 第一条** | 否则解析报错 |

`displayDescription` 草稿（45 字，卡在区间内）：

> 把散落文档编译成有边界、可执行的条目，生成 AI 与新人能照做的 SOP，支持增量更新与版本管理。

`quickPrompts` 三条：

1. 把我这个文件夹的文档整理成可执行的知识库
2. 检查我的知识库哪些条目太空洞
3. 把这份访谈整理成一条可复用的经验

`agents/knowledge-compiler.md` 的 frontmatter：`name` / `description`（英文，AI 据此判断何时激活）/ `displayName` / `profession` / `maxTurns: 100` / `skills: [narwhal]`。

**注意**：`maxTurns` 要给足。编译一个领域要读几十个文件、写十几条条目，50 轮会中途截断（官方默认 50，专家团代码里见过 100）。

### 3.3 入驻（可与打并包行）

个人主体：真实姓名 + 身份证 + 手机号 + 收款信息 → 审核 → **微信扫码签约**。这一步不做完，付费资产发布不了。审核最迟 24h 返。

## 四、定价

| 资产 | 模式 | 价格 | 理由 |
|---|---|---|---|
| narwhal 技能 | 免费 | ¥0 | 换量，不参与收入 |
| 知识库编译师 | **一次性买断** | ¥99 起 | 见下 |

**为什么是买断不是订阅**：
- 平台订阅制要求"订阅期内可持续使用"，隐含持续交付义务；
- 我们的增量价值（季度体检、CHANGELOG）需要人肉投入，C 端 ¥39/月 撑不起；
- 买断与"库在你手里、永久可用"的产品叙事一致；
- **且选定不可改**，选错代价高，买断的下限更安全。

**为什么是 ¥99 起步**：低于 ¥100 属冲动区间，退款摩擦（7 天无理由）影响小；同时这是一个"试错价"，不是价值定价。等使用量上来、评价积累后，**新开一个资产**定 ¥199（老资产价格不可改，但可以发 v2 资产）。

⚠️ **定价前必须在客户端专家市场里翻 20 个同类付费专家，看实际价格带**。官方文档不给价格分布，拍脑袋定会踩空。

## 五、运营：三件事，一个现实预期

### 现实预期先摆出来

**这两个市场目前没有强自然流量分发。** 推荐位按"使用热度 / 新上架 / 编辑精选"排，本质是把已有热度再分配。指望"上架就有量"不成立。所以所谓运营，实际是**自己带人进市场**，市场只负责承接转化。

### 三件事

**① 搜索词工程（上架当天做完）**
`tags` 3 个 + `description` 里塞用户真会搜的词：知识库、SOP、经验、文档整理、培训、交接、个人知识管理。用户搜的是"怎么把文档变成能用的东西"，不是"知识编译"。

**② 站外内容：给结果，不给功能**
唯一有效的素材是**前后对比**：一堆乱文档 → 一张 MOC + 12 条带数字的条目 + 一份 CHECKLIST。发小红书 / 即刻 / V2EX / 公众号，标题写结果（"把 200 篇文档压成 30 条能直接干活的 SOP"），不写"我做了个 skill"。技术社区（V2EX、GitHub）指向免费 skill，非技术社区指向专家市场。

**③ 使用量是唯一硬指标**
卡片上公开显示，前 100 次使用决定后面能不能被推荐。所以免费 skill 要**极力降低首次使用门槛**：默认给 demo 素材，用户一句话就能看到成品，不要让他先准备文档。

## 六、三个必须先验证的风险

| # | 风险 | 为什么致命 | 怎么验 |
|---|---|---|---|
| 1 | **付费资产"在云端运行"** | narwhal 的核心卖点是"库在你本地、可移植、离线可用"。如果付费版跑在云端、读不到用户本地文件，"把文档编译成你自己的库"这个交付就断了 | 上架一个 ¥1 的测试专家，看 `scripts/*.py` 能否用 Bash 读写用户本地路径、产物能否落到本地 |
| 2 | **付费模式不可改** | 免费转付费无路，反之亦然 | 已在策略上规避：两个资产分开 |
| 3 | **市场自然流量低** | 上架 ≠ 获客，没有站外内容就没有量 | 上架后 2 周看安装数，<50 说明只能靠自传播 |

风险 1 如果成立（云端隔离本地文件），付费专家要改成"云端生成 → 导出 zip → 用户下载落本地"，仍然成立，但 `displayDescription` 里"支持增量更新"这句要改口径。

## 七、修订后的路线（覆盖 POSITIONING 第六节 P0）

| 阶段 | 做什么 | 通过标准 |
|---|---|---|
| **P0-a 打包（2 周）** | 补齐 `SKILL.md` 市场字段；搭专家壳（`plugin.json` + 头像 + 3 tags + 3 prompts）；入驻签约 | 本地 `zip` 提交解析通过，不报错 |
| **P0-b 免费上架** | 只上 `narwhal` 技能，¥0；配 3 条示例 + demo 素材 | 4 周内安装 ≥100，或有 ≥10 条有效使用反馈 |
| **P0-c 付费上架** | 上「知识库编译师」，¥99 买断 | 4 周内成交 ≥10 单（约 ¥1000），退款率 <20% |
| **P1 看数据分叉** | 成交 ≥10 → 继续做第二个垂直专家（如"访谈萃取师"）；成交 <3 → 说明 C 端不为此付费，转回交付服务（POSITIONING 的 A 阶段） | 用真实成交决定，不用感觉 |

**技术债不再阻塞上架，但会阻塞成交**：`triage.json` 规范化、质检报告模板这两段没做，专家演示时无法给用户看"分诊结论"和"质检分数"——而这两样恰恰是"专业感"的来源。建议在 P0-c 之前补完，否则专家看起来像个玩具。

## 八、两周内的动作清单

1. 补 `skills/narwhal/SKILL.md` 的市场 frontmatter（含 3 条 `examples_zh`）
2. 写 `packaging/expert/` 下的专家壳：`plugin.json`、`agents/knowledge-compiler.md`、`README.md`
3. 生成头像（512×512 PNG ≤500KB，插画风，与"编译/档案/鲸"意象一致）
4. 跑一次本地打包自检（字段齐全、`defaultInitPrompt` 与 `quickPrompts[0]` 一致、中文描述 40–50 字）
5. 开放平台入驻：填资料 → 审核 → 微信签约
6. 免费技能先提交，拿到一次审核反馈后再提交专家（避免两个资产同时被拒、来回改）
