# Narwhal 产品形态与定位（v0.1）

> 一句话结论：**我们做的不是软件，是"知识编译"这项可计价的服务；软件只是这条产线的内部工具，未来才可能变成商品。**

## 一、先把产品类型定死

narwhal 属于 **Productized Service（服务产品化）**，不属于 SaaS、不属于工具、不属于内容产品。

判定依据（三条全中才算）：

| 判据 | narwhal 的答案 |
|---|---|
| 交付物是**结果**而非能力 | 客户拿到的是"他的库 + 他的 SOP 包 + 质检报告"，不是账号权限 |
| 单价由**成果**决定而非席位 | 按领域计价 ¥2k–8k，与用多少人无关 |
| 质量靠**流程**保证而非师傅 | eval 11 项打分 + 四条门禁 + 版本号 |

这三条决定了：**产品经理的第一优先级不是功能，是"同一批料、两个人做、结果一样"。**

## 二、为什么不是另外三种

| 候选 | 为什么不选 |
|---|---|
| **笔记 / PKM 工具**（Obsidian、Notion、Logseq） | 他们的价值在"存"和"连"，我们不在那一层。客户已经有笔记了，问题是笔记**不能直接干活的**——没有数字、没有反例、没有边界 |
| **通用 RAG 平台**（Dify、RAGFlow、Coze） | 他们的护城河是集成广度与模型接入，个人打不过。且 RAG 解决"找得到"，我们解决"找得到的这句话**能不能直接用**" |
| **知识管理咨询**（传统咨询公司） | 交付物是一份 PPT，落不了地。我们交付的是可执行、可回归、可版本化的资产 |
| **App / SaaS 优先** | 5 个付费客户之前做 SaaS = 用工程时间买不确定性（PRODUCT.md 已论证） |

## 三、一条产线，三种售卖（不是三选一）

关键认知：**代工、标准品、平台是同一条知识生产线的三种售卖方式**，不是三个产品。

| | A. 代工（客户给料） | B. 标准品（我们选料） | C. 平台（租产线） |
|---|---|---|---|
| 形态 | 一次性建库交付 | 领域成品库（数字商品） | 多人协作 / 权限 / 审计 |
| 谁付钱 | 有文档囤积的中小团队 | 同行业从业者，一对多 | 团队，按席位/库 |
| 单价 | ¥2k–8k / 领域 | ¥299–999 / 份 | ¥500–2k / 月 |
| 单位经济 | 人力重、不可复用、毛利高 | 一次生产、多次售卖、边际近零 | 算力+运维，需规模摊薄 |
| 核心风险 | 交付即失联 | 需求是猜的 | 工程量被低估 |
| 顺序 | **第一步** | **第二步** | **第三步** |

**为什么顺序不能反**：A 阶段真正产出的是**配方**——什么料分诊成经验、条目长什么样、门禁阈值定多少、人天怎么估。这些只能从真实客户身上试出来。B 拿配方做标准品，验证"没人陪跑也有人买"。C 才有资格把配方写成软件，因为此时每一步判据都已被验证过。

跳过 A 做 B，会做出没人要的成品库；跳过 B 做 C，会做出没人用的系统。

## 四、定位：知识编译（Knowledge Compilation）

**品类词必须自己造，不能用"知识管理"。** 因为"知识管理"在客户脑子里等于"又一个笔记软件"，一旦落进那个类目，报价就会被压到 99 元/年。

| | 知识管理 | 知识编译 |
|---|---|---|
| 处理对象 | 信息 | **判断** |
| 成功标准 | 找得到 | **AI / 新人能照着做对** |
| 产物 | 页面、双链、标签 | 条目（有数字/反例/边界/⭐）+ SOP/CHECKLIST/PLAYBOOK |
| 计价方式 | 按席位 | 按领域 |
| 谁会买 | 想整理的人 | 怕人走了经验就没了的人 |

**对手不是软件，是"人走了，经验就没了"。** 这句话才是客户的真实痛感，也是预算来源——它对应的是招聘成本、培训周期、交付质量波动，不是"工具订阅"这一栏预算。

### 客户（ICP，第一版）

| 优先级 | 谁 | 为什么 |
|---|---|---|
| 1 | 3–15 人专业服务团队（咨询/设计/教培/医疗/工程） | 文档多、靠人脑、**有人员流动**、决策链短 |
| 2 | 独立专家 / 顾问 | 想把自己的方法论卖出去，天然理解"技能包"的价值 |
| 排除 | 大企业 | 采购周期 3 个月起，验证阶段耗不起 |
| 排除 | 个人知识爱好者 | 会觉得贵，且不产生转介绍 |

### 对客户说的一句话

> **把你团队里最厉害那个人的判断，做成任何人（包括 AI）都能照着执行的包。**

注意这句里没有"知识库""检索""embedding""AI 记忆"——这些是我们的实现，不是客户的收益。

## 五、护城河：代码开源之后还剩下什么

skill 本体 MIT、164 个文件已公开，检索算法全部可 fork。所以护城河必须落在代码之外，共四层：

| 层 | 内容 | 能 fork 吗 |
|---|---|---|
| L1 配方 | 分诊判据、条目模板、四条门禁阈值、报价人天模型 | 能抄走，但抄不到"为什么这么定" |
| L2 基准 | eval golden set（12 份 archive + 13 份真实 web 文件 + 阈值） | **不能**——这是我们踩坑换的，且持续增长 |
| L3 成品库 | B 阶段做出来的领域标准品 | 不能，是资产不是代码 |
| L4 承诺 | 季度体检 + CHANGELOG + 3 个月维护 | 不能，是时间 |

**唯一值得建付费墙的技术能力是"规模"**（多库/权限/审计/协同），因为它的工程量是单机版的 20 倍，fork 的人懒得抄。检索和编译永远不做墙——做了也没用。

## 六、路线图（按可验证假设切，不按功能切）

> ⚠️ **本节 P0 阶段已被 `docs/GO-TO-MARKET.md` 第七节替代**：分发（上架技能市场 / 专家市场）前置到交付服务之前，P1–P3 不变。原 P0 的技术债（`triage.json`、质检报告模板）改为"不阻塞上架、但阻塞成交"。

| 阶段 | 时间锚 | 做什么 | 验证什么假设 | Go / No-go 标准 |
|---|---|---|---|---|
| **P0 收口** | 现在 – 2 周 | 补齐七段里还靠人肉的三段：`triage.json` 规范化、质检报告模板、（版本管理已完 `wiki_version.py` ✓） | 一个人能不能在 3 天内交一个领域 | 完整跑通 1 个领域，全流程 ≤3 人天，eval ≥90 |
| **P1 代工** | 1 – 3 月 | 接 3 个买断单，尽量同行业 | 有人愿为"成品库"付 ¥2k+ | 3 单成交 + ≥1 单转介绍 + 实际人天误差 <20% |
| **P2 标准品** | 3 – 6 月 | 把 P1 里最高频的领域做成可复制成品库，一对多卖 | 不用陪跑也有人买 | 单个领域卖出 10 份 |
| **P3 平台** | 6 – 12 月 | **只做规模能力**（多库/权限/审计/计费），检索与编译仍留本地 | 团队愿为协作付月费并续费 | 3 个团队续费 ≥2 季度 |

P3 的边界要写死：**SaaS 不做检索。** 理由见第五节——做进去也没护城河，还会把运维成本背上身。

## 七、禁区（比路线图更重要）

| 禁区 | 一旦越线的后果 |
|---|---|
| 对外宣称"AI 记忆 / 第二大脑" | 落进 PKM 类目，报价被压到两位数 |
| 承诺"全自动一键建库" | 必然产出空洞条目，砸掉"经验 > 信息"的招牌 |
| 接"帮我整理一下这些文档" | 那是文件管理，不是知识编译，客户预算完全不同 |
| 承诺"知识永不丢失" | 该承诺的是**可验收**：分数、版本、CHANGELOG、每句可溯源 |
| 把审校也自动化掉 | 访谈挖料 + 事实审校这两个人工点**是价值来源，不是成本**，去掉就变成摘要工具 |
| 按检索档位收费 | 代码在 MIT 仓库里，用户会问"我为什么要买"（PRICING.md 已否决） |

## 八、现在就该做的三件事（P0）

1. **`triage.json` 规范化** —— 七段里唯一还没脚本化、且直接卡住报价的一环（分诊结论决定人天）
2. **一页质检报告模板** —— 对外的交付物，不是内部日志；客户看不到分数就不信
3. **新人实跑记录** —— "可交接"这条至今未测，而它最能说明这是产品还是"你在卖自己"

> 收口一句：**P0 不产出新功能，只产出"可重复"。有了可重复，才谈得上定价、招人、做标准品。**
