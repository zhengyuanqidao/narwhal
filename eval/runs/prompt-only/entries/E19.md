## 一句话结论

攻击者不攻系统，攻的是系统信任的那一层：CircleCI 工程师笔记本 2022-12-16 被植入恶意软件、盗走带 2FA 的有效 SSO 会话；Okta 第三方支持工程师笔记本被攻破；ESLint 维护者 npm 账号被盗发布恶意包；Xubuntu 官网下载链接被换成恶意 zip。

## 展开与个人判断

原文事实：CircleCI  unauthorized 第三方用部署在工程师笔记本上的恶意软件窃取带 2FA 的 SSO session，机器于 2022-12-16 被攻陷，杀毒软件未检出，cookie 被盗后冒充员工并升级访问到部分生产系统。Okta 黑客组织访问了第三方支持工程师的笔记本。ESLint 在 2018-07-12 有攻击者入侵维护者 npm 账号发布恶意包。Homebrew 一个刚提升权限的 GitHub personal access token 从 Jenkins 泄露，可对多个仓库 `git push`。Xubuntu 官网被攻陷，下载链接改为恶意 zip。Cloudflare 处理 Okta support system 的认证令牌被窃，凭管理员权限访问其 Okta 实例（Zero Trust 架构阻止了对客户系统的影响）；另一起 Salesloft Drift 的 Salesforce 集成 OAuth 凭据被窃，用于外泄 Cloudflare Salesforce 支持案例数据。BrowserStack 一台带 Shellshock 漏洞的旧原型机上有密钥，导致生产系统被入侵。

我的判断：这些入口的共同点是**信任被借用**：2FA 保护的是账号，不是 session cookie；npm 账号保护的是发布权，不是包内容；下载站保护的是页面，不是二进制。我要的是把「身份」和「能力」拆开：短时凭证、发布签名、产物校验和、以及第三方集成的最小权限 + 定期轮换。特别提醒：带外变更之所以能生效，往往就是凭据层先失守，见 [[带外 WAF 变更：不在 Terraform 里就等于没发生]]；而凭据泄露之后能造成多大破坏，取决于操作工具有没有护栏，见 [[一条命令删错库：手误的杀伤半径]]。

事实来自公开复盘，判断为本次提炼，未经用户复核。

## 适用边界/反例

- 反例：全面零信任改造成本高，别指望一次到位；优先保护「能签发其他凭据」的那几个节点（CI、发布账号、IdP）。
- 边界：2FA 仍然有效，只是不能防 session 窃取；不要因为这条就否定 2FA。
- 反例：轮换太频繁会诱发人们把凭据写进脚本/便签，反而扩大泄露面。

⭐ 攻击者不攻你的系统，攻你系统信任的那一层——先保护能签发凭据的节点。
