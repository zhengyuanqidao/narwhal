# 冗余只在故障域独立时才成立

**一句话结论**：多一套备份不等于多一份可用性——如果两套备份共享同一个触发条件，它们会在同一秒一起失效。

## 展开

硬件与供电故障（Hardware/Power Failures）这一类里，最值得记的不是"机房会断电"，而是"冗余怎么一起倒"。Cloudflare 波特兰机房因为级联安全断路器的整定值（breaker coordination）设置错误，一次完全断电绕过了所有冗余供电路径——冗余在图纸上齐全，在物理上被一个参数短路了。Google 则出现过同一区域内多套冗余冷却系统同时失效。Amazon 圣保罗机房更典型：切换过程中一台发电机前的断路器跳开，另一台发电机独立发生机械故障，剩下的健康发电机被过载拖垮，自动电源控制系统也失灵，最终只能人工上发电机。

这些案例指向同一个判断：**冗余的价值取决于故障域是否独立，而不是备份数量**。同厂商、同批次的硬件，同一条母线，同一个配置模板，同一次变更——都会把"两套"变成"一套"。

还有一个更扎心的细节：Amazon 那台备用发电机两个月前刚通过负载测试，还每周做上电测试，切换时仍然失败。**测过的路径，不等于切换时的路径。**

## 适用边界 / 反例

反例是把"多可用区部署"当成结论——如果所有可用区由同一个控制面下发配置，那次配置变更就是共同故障域。可行的边界做法：对每一个"冗余"标注它依赖的共享资源（同一电源、同一控制面、同一镜像、同一变更窗口），共享项越多，冗余系数越接近 1。这条对基础设施和分布式系统都成立；对无状态单体应用收益有限。

⭐ 一句话给三年后的自己：问"这两套东西什么时候会一起坏"，比问"有几套"有用得多。
