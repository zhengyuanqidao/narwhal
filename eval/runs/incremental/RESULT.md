# 增量追加换手验证（A2 零脚本版 v1.0.2）

> ⚠️ **本目录下 `incoming/` 与 `wiki/raw/2026-11-24-*.md` 中的经营数字（214 次下载、3 单 ¥27、转化 1.4%、¥9 定价等）全部是为测试合成的验证语料，不是真实经营记录，不代表任何真实成交或平台数据。** 编造这些数字的目的是让溯源率/覆盖率判据有可核对的锚点；真实数据请以平台后台为准。

> 目的：验证「下次用户又有新文件」这条路径是否真的能由**使用者的 Agent 自助跑通**，不需要作者在场、不需要重述需求、不需要跑脚本。
> 日期：2026-11-24 ｜ 方式：独立 Agent 换手 + 脚本版 doctor/report 机械复核（不信自述）

## 发现的两点边界（如实记录，不掩饰）

1. **判据口径差异**：脚本版 `report.py` 按字符 2-gram 判覆盖，列出 `COMPETITIVE-INTEL.md` 两章未命中（83.3% 仍 PASS）；零脚本版按语义判「实质内容有无条目覆盖」，结论是「未覆盖章节 0」。这是 v1.0.2 §一 已声明的「精确数字 vs 定性结论」差异，**不是编造**，但读者拿两份报告对不上时应知道原因。要可签字的精确报告请用带脚本版。
2. **存量条目的历史包袱**：基线 9 条中 7 条正文无 `[[...]]` 出链（只写在 frontmatter `links:`）。模式 G 规定「不重写存量条目」，所以本次没有回补，Agent 已把它列入遗留项交用户裁决。若用户希望全库统一，需**明确说一句**「顺手把旧条目也补齐双链」——这是可选项，不是默认动作。

## 结论

**「又有新文件 → 一句话 → 自助增量」这条链路闭环了**：独立 Agent 零脚本跑通，旧内容零覆盖、新内容零断链、收尾产物齐全、版本可追溯。作者不需要在场，符合 OPC「可复制、无需卖家在场」的口径。

未验证（不能自动替代真人）：真实非技术用户是否会照着 `SELF-SERVE-GUIDE.md` 说出正确的那句话、以及是否愿意转发 `index.html`。
