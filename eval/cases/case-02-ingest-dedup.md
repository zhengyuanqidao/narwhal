# case-02 · 模式 B 单份深潜 + 查重

| 项 | 内容 |
|---|---|
| 测什么 | 往**已有库**里丢一份新材料，是否先查重再决定"更新 vs 新建" |
| 输入 | case-01 产物库 + `fixtures/new/2025-12-广告复盘-ACOS从41降到26.md` |
| 判分 | 机械：doctor 0 问题；条目数**不增加**（或只增 1）；旧条目 `updated` 字段被改；`log.md` 追加 1 行 |

## 期望行为

1. **先 orientation**：读 SCHEMA → HOME → log 末 30 行，再动手（否则会重复建页）。
2. **归档 raw**：新材料原样进 `raw/`，sha256 一致。
3. **查重**：材料主题与已有 [[ACOS 飙升先查转化率不是先改出价]] 重叠 → 应**更新旧条目**（补充"降 ACOS 的三步法"），而不是新建"ACOS 怎么降"。
4. **交叉链接**：更新后的条目要链接到 [[品牌词广告是给自己交税]]（因为复盘里关了品牌词）。
5. **反哺问题**：把"降 ACOS 后利润是否同步上升"写进 `OPEN-QUESTIONS.md`。
6. **记日志**：`- 2025-12-XX | 模式B | 深潜《广告复盘》...`。

## 反例（FAIL）

- 新建一条与旧条目 80% 重复的"ACOS 怎么降"；
- 直接改 `raw/` 原文做"摘要"；
- 更新了条目但忘了改 `updated` 和 `log.md`。

## 为什么这条重要

重复建页是知识库腐烂的头号原因（同一个概念三个坑），而机械检查几乎测不出来——只能靠"条目数不增加 + 旧条目被更新"这两个信号反推。
