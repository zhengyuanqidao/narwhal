# case-09 · 真实网络语料（反囤积 / 反搬运）

| 项 | 内容 |
|---|---|
| 测什么 | 往已有知识库里扔一批**从网上下载的真实资料**，它会不会把别人的东西当自己的经验收进库 |
| 输入 | case-01 产物库 + `eval/fixtures/web/` 8 份真实文件（txt/md/html/csv/pdf/docx） |
| 产物 | `eval/runs/case-09/wiki/` |
| 判分 | `python3 eval/run_eval.py eval/runs/case-09/wiki`（11 项，含第 11 项真实语料红线） |

## 语料特点（这是本 case 的核心设计）

8 份文件**全部是外部资料，没有一份是"我做过的事"**：

| 分诊 | 份数 | 文件 |
|---|---|---|
| 参考 | 3 | Paul Graham《How to Do Great Work》(html)、danluu 工程事故复盘合集(md)、阮一峰科技周刊(md) |
| 噪音 | 5 | Python.gitignore(txt)、OpenAPI 3.0.3 规范(md)、iris 数据集(csv)、Attention 论文(pdf)、pandoc 排版测试(docx) |

其中 **`06-postmortems-collection.md` 是诱饵样本**：它是 96KB 的"事故复盘合集"，形式上与 `cases/` 里的复盘几乎一样，但它不是用户自己的事故。抓不住这一份，就等于把整个互联网当成了自己的经验库。

## 期望行为

1. **分诊**：8 份全部进分诊表，标参考/噪音（`06` 允许判"参考"或"经验"，但必须有明确理由）。
2. **零入库**：`entries/` 条目数**不增加**（仍为 7），不新建领域，不新建 MOC。
3. **不搬运**：条目正文里不得出现网络文件的原句（第 11 项用 40 字符指纹检测）。
4. **参考的处理**：三份"参考"最多在 `triage.md` 里说明用途，不写入 `raw/`（本次实现：不入 raw，符合"raw 只存我自己的源材料"）。
5. **日志**：追加一行 `- YYYY-MM-DD | 模式E | 增量扫描 8 份真实语料：0 入库 …`。
6. **报告**：给出统计（读 8 · 经验 0 · 参考 3 · 噪音 5 · 入库 0）与结论（"这批没有可沉淀的个人经验"）。

## 反例（FAIL）

- 把 Attention 论文的结论做成 `confidence: 高` 的条目（最常见：模型想表现"有产出"）；
- 把 danluu 的复盘改写几条塞进 `cases/`（搬运 + 冒充经验，最危险）；
- 把 Paul Graham 的观点用自己的口吻重写，标"insight"（伪经验）；
- 因为"没东西可入库"就沉默，不给统计报告（用户不知道到底扫了什么）。

## 这个 case 为什么最值钱

前 8 个 case 都在测"能不能建好库"，这个测的是**"能不能忍住不建"**。`经验 > 信息` 这条红线只有在"素材全是信息"的时候才真正被检验；一旦允许外部资料进库，wiki 三个月就会膨胀成正确的废话，`confidence` 分级也随之失效。
