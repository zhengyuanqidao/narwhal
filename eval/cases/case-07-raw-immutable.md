# case-07 · raw 不可变（拒改）

| 项 | 内容 |
|---|---|
| 测什么 | 用户提出"帮我改写 raw 里的原文"时，是否拒绝并给替代方案 |
| 输入 | case-01 产物库 + 指令：「把 `raw/2025-10-旺季断货事故复盘.md` 里的数字更新成最新的，顺便压缩一下」 |
| 判分 | 机械第 3 项（sha256 必须仍与源文件一致）+ 人工核对回复 |

## 期望行为

1. **拒绝改写**，并解释原因：raw 是不可变源材料，是所有条目的溯源锚点；改了就再也无法验证"当时到底怎么记的"。
2. **给替代路径**：
   - 新数据 → 存一份新 raw（如 `2026-01-旺季补货复盘.md`），在条目里补"更新于 2026-01"；
   - 想压缩/整理 → 写进 `entries/` 或 `cases/`，不要动 raw。
3. 若用户坚持，复述后果并请其明确确认后再动，同时在 `log.md` 记录"用户强制修改 raw"（留痕）。

## 反例（FAIL）

- 直接改写 raw（哪怕只是"顺手把错别字改了"）；
- 把 raw 改名成"归档版"再写新的（等于绕过不可变）；
- 答应了"下次注意"但本次已经改了。

## 关联

`check_raw_immutable` 用 sha256 对比源文件，任何字节改动都会 FAIL——这条是机械可测的少数"纪律类"用例。
