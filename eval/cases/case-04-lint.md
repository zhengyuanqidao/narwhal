# case-04 · 模式 D 体检（注入坏数据）

| 项 | 内容 |
|---|---|
| 测什么 | 脚本能不能抓到 4 类结构问题；agent 能不能抓到脚本抓不到的**矛盾** |
| 输入 | case-01 产物库 + `fixtures/inject/` 覆盖进去 |
| 判分 | 脚本应报 **4 处**问题（断链 1、孤儿 1、缺 frontmatter 1、缺文件?）；人工核对矛盾是否被指出 |

## 注入的坏数据

| 文件 | 病症 | 期望检出 |
|---|---|---|
| `entries/广告投放/断链测试条目.md` | `links: ["[[这个条目根本不存在]]"]` | ✗ 断链 1 处 |
| `entries/供应链库存/孤儿条目-安全库存.md` | 无出链也无入链 | ⚠ 孤儿 1 处 |
| `entries/选品/缺元数据测试条目.md` | 无 frontmatter | ✗ 缺 frontmatter 1 处 |
| `entries/广告投放/矛盾条目-A/B.md` | 两条结论互斥（ACOS 高该降价 vs 该查 CVR） | 脚本**查不出**，必须由 agent 报出并请用户裁决 |

## 期望行为

1. 先跑 `python3 skills/narwhal/scripts/wiki_tool.py doctor <wiki>`，报出 3 类结构问题。
2. 再做**矛盾检测**（脚本之外）：指出 A/B 两条互斥，给出裁决建议（保留 B，因为 B 有 2025-09 实测数据支撑，A 是早期错误认知），并建议 A 标记 `> ⚠️ 与 [[矛盾条目-B]] 存在矛盾`。
3. 对照 `OPEN-QUESTIONS.md` 报**覆盖缺口**：哪个领域长期没有新条目。
4. 修复动作写进 `log.md`（`- YYYY-MM-DD | 模式D | 体检：修复断链 X、合并孤儿 Y`）。

## 反例（FAIL）

- 只跑了脚本就交差，没做矛盾检测（症状：报告里完全没有 A/B）；
- 直接删掉坏条目而不解释（体检不是删库，要先报告再问）；
- 把 A 直接改成和 B 一样的结论（掩盖了"认知演化"这个有价值的信息——正确做法是保留并标注）。
