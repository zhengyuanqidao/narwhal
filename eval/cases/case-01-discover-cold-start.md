# case-01 · 模式 E 全域扫描冷启动（主用例）

| 项 | 内容 |
|---|---|
| 测什么 | 从零建库：采集 → 分诊 → 聚类 → 批量入库 → 体检，端到端是否守纪律 |
| 输入 | `eval/fixtures/archive/` 10 份文档 + `/root/.nvm/README.md` + `/root/.oh-my-zsh/README.md` |
| 产物 | `eval/runs/case-01/wiki/` |
| 判分 | `python3 eval/run_eval.py eval/runs/case-01/wiki` → 10 项全 PASS |

## 期望行为（逐条可验）

1. **先采集再分诊**：12 份文件全部出现分诊表里，不能漏扫（漏扫 = 分诊准确率掉到 90% 以下）。
2. **噪音必须跳过**：装修预算清单、两个开发工具 README 标"噪音"，且**不复制进 `raw/`**。
3. **经验优先**：6 份经验素材全部原样归档进 `raw/`，sha256 与源文件一致。
4. **参考降级**：行业报告 / 竞品分析 / 学习笔记标"参考"，不得以 `confidence: 高` 入库；学习笔记这种"作者自己都说没验证"的通用知识，正确做法是不收或标 `低·外部参考`。
5. **聚类 3~7 域**：本例应为 4 个领域（选品 / 广告投放 / 供应链库存 / 团队协作），且**先提交候选清单等用户确认**再批量入库。
6. **每域先出 MOC**：地图优先，条目全部挂进地图。
7. **单次精读 ≤20 份**：本例 12 份，不触发；若素材超 20 份，须先列清单让用户排优先级（见 case-01b 待补）。
8. **结束给统计报告**：读了 N 份、经验 X、参考 Y、跳过 Z、入库 M 条、建议的下一个深潜主题。

## 反例（出现即判 FAIL）

- 把装修清单也归档进 `raw/`（噪音泄漏）；
- 把行业报告的内容写成 `confidence: 高` 的条目（违反"经验>信息"）；
- 归档 raw 时顺手"整理格式"导致 sha256 变化（违反 raw 不可变）；
- 4 个领域全建了，但 MOC 里只挂一半条目（孤儿）；
- 条目正文写成百科腔、没有"我"的判断（机械检查测不出，**人工评审要点**）。

## 人工评审要点

- 条目里是否有第一人称判断（"我后来改成 X，因为 Y"），而不是复述原文；
- 每条是否有"适用边界/反例"段落；
- `log.md` 是否记录了分诊统计，而不是一句"完成扫描"。
